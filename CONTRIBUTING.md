# Contributing to BrowserPair public resources

Thank you for helping improve BrowserPair's public documentation and developer resources.

## Choose the right repository

- Product reports and feature requests: https://github.com/BrowserPair/browserpair/issues
- Documentation: https://docs.browserpair.com/ and its linked source repository
- Integration code: https://github.com/BrowserPair/examples
- Reusable workflows: https://github.com/BrowserPair/skills
- Ecosystem resources: https://github.com/BrowserPair/awesome-browser-agents

The application source is maintained separately and is private. Public repositories do not grant access to production systems or private code.

## Report an issue

Include what you expected, what happened, reproducible steps, the relevant version and the smallest redacted example. Separate verified behavior from a hypothesis. Check https://status.browserpair.com/ for an existing outage.

Do not post agent keys, device credentials, cookies, private account data, personal details or unredacted logs. Use https://browserpair.com/support for private account matters.

## Suggest a change

Keep pull requests focused. Explain the problem, the resulting behavior and how you checked it. Preserve existing published URLs or add redirects. Verify API fields and UI labels against the current product.

Examples must use placeholders or environment variables for credentials and clearly describe any live actions. Skills need explicit applicability, inputs, existing authority requirements, verification and recovery behavior.

Disclose affiliations when suggesting an ecosystem resource. No paid placement, fabricated benchmarks or unsupported competitor claims.

## Licensing

New public resource repositories include an MIT license. Contributions should be compatible with the destination repository's license. Product names and logos identify their owners; do not imply third-party endorsement.
